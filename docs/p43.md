# P43 open-weights triage

P43 is an offline development experiment on Muse Spark Open, hosted through
Baseten's synchronous Model APIs. The existing `Glimmer` client name is retained
for compatibility; it accepts the configured model ID and needs no change to
`Spark.ask` or the shared response store. Production screening never calls triage.

## Run

First restore the saved screenings for a registered, non-void v2 dev screen run.
Do not substitute test inputs, reconstruction scripts, labels or API demo jobs.

```powershell
uv run python -m preflight.eval.triage screen-20261102T173132 --screenings C:/retained/dev-screenings --check-inputs
```

The preflight checks require every original media part, matching screening IDs,
source snapshots and completed checks. Older registered cohorts remain tied to
their original item rows when the development manifest grows. Unexpected IDs
are rejected before their content is opened. The preflight does not load labels
or credentials.

Configure `BASETEN_API_KEY` locally and
`GLIMMER_MODEL=meta-models/muse-spark-open-1026`. The unversioned alias is accepted
as an override, but returned HTTP 403 during this checkout's smoke test. Then:

```powershell
uv run python -m preflight.eval.triage screen-20261102T173132 --screenings C:/retained/dev-screenings
```

No Meta Model API key is required. `--model` overrides `GLIMMER_MODEL`; other
model families are rejected. The endpoint is fixed to Baseten. To repeat an
experiment without provider calls, add `--replay --cache <recorded-cache>` and
use the same model, prompt and inputs. The report records cache mode; replay
timings are not live inference timings. An existing output directory is refused.

Once the key is configured, a separate synthetic live smoke needs no saved bundle:

```powershell
uv run pytest tests/test_triage.py -m live -k baseten_triage_live -s
```

It uses a fresh response cache and prints only returned model, date and usage.
That verifies the hosted path, not development recall or net savings.

Each ad's on-screen text and transcript units go into one request, with media
identity, modality and time spans. Unit IDs remain distinct across media and
modalities. The model returns only IDs and boolean review decisions. Missing,
duplicate, unknown or malformed decisions retain the whole batch for review and
increment its fallback count. Provider failures abort the experiment rather than
registering an incomplete result. The completed report is written last.

Muse Spark Open does not support structured outputs or JSON mode according to
the [provider documentation](https://docs.baseten.co/inference/model-apis/overview);
the parser therefore validates ordinary text responses locally, after unwrapping a reply
that comes back inside one Markdown code fence. Exact register
wording still counts as requiring review. Ad copy is treated as untrusted input.

## Evidence and limits

Ignored output under `data/work/triage/` contains per-item counts and timing,
response decisions and token usage, false skips identified by original evidence
IDs and matched claim indices, and a report with model, host, prompt, source-run
identity, code/input hashes and revision/dirty state. A completed run, live or
replayed, is then registered in `results/runs.csv` as stage `triage` (`claim_units_kept`,
`units_skipped`, `chars_skipped`, `triage_tokens` and `triage_fallbacks` per ad), with
per-ad counts in `results/runs/<run_id>.csv`; a run that fails partway registers
nothing. Treat the result as a development experiment.

A claim-bearing unit matches a ground-truth breach with the shared `holds`
line matcher. Report both kept/total claim-bearing units and kept/available
ground-truth claims. Visual claims and claims spanning several units may have no
matching individual text unit; the coverage denominator exposes this gap.
Labels describe breaches, not every valid health/nutrition claim, so this is not
an estimate of recall over all health claims. Prompt correctness also needs a
human read of false skips and a provider-backed development measurement.

Skipped units/ad and skipped/total units estimate potential downstream input
reduction. Skipped characters (per ad and as a share) track input tokens more
closely than unit counts, and triage's own tokens per ad are reported beside them.
`matches_full_pipeline_recall` is true only when nothing claim-bearing was
skipped, since the full pipeline judges every unit; while it is false, triage
stays a demonstration of the open-weights path. They are not net monetary savings: upstream OCR/ASR has already run,
downstream prompts batch units, and triage itself costs tokens and time. No new
extraction or judge stage runs in this experiment, so avoided dollars and the
effect on end-to-end recall remain unmeasured. Any future production gate needs
founder confirmation of [provider terms](source-terms.md), recall comparison,
real marginal-cost measurements and a separate reviewed implementation.

### Dev measurement, 3 November

Run live on the saved screenings of `screen-20261103T172541`, a registered, non-void
single-sample v2 dev run of the ten near-miss ads N01 to N10 (claims_v5, judge_v8),
with `meta-models/muse-spark-open-1026` on Baseten and `triage_v1`. Registered in
`results/runs.csv` as run `triage-20261103T173048` (stage `triage`); per-ad counts are
in `results/runs/triage-20261103T173048.csv`. No fallbacks; every returned model ID was
the pinned one. An earlier unregistered measurement on `screen-20261102T170916` is
superseded, because its saved screenings and response cache are no longer on disk.

| Measure | Result |
| --- | --- |
| Claim-bearing units kept | 10 of 10 (no false skips) |
| Ground-truth claims in some unit | 10 of 10 |
| Units skipped | 72 of 104 (69%), 7.2 per ad |
| Characters skipped | 1,937 of 3,510 (55%), 194 per ad |
| Triage tokens per ad | 3,414 (11,535 in and 22,605 out over ten ads, reasoning included) |

What it skipped: pack sizes, flavour, directions, the "Team-written test ad" caption,
and in 9 of 10 ads the food supplement statement ("should not be used as a substitute
for a varied and balanced diet"). That last one matters. The statement is not a claim,
but the judge and the near-miss scoring read it as the statement 15.7 requires, so a gate
built on `triage_v1` would have to keep required statements as well as claims.

The saving does not cover triage's own tokens. A token of English text covers at
least one character, so skipping about 194 characters per ad saves at most about 194
input tokens in each downstream call that reads them, against about 3,400 triage
tokens per ad. Baseten's price for Muse Spark Open is not on record, so this compares
tokens, not dollars. Triage could pay for itself only on far longer ads, or if it
decided which frames go to SAM, the most expensive stage per ad (`docs/plan.md`).

The ten items are all positives that differ from a compliant ad by one line, so the
run says nothing about clean ads, and ten claims is a small sample. Recall matches
the full pipeline's on these items, but under the issue's watch-out triage still
does not gate screening: it uses more tokens than it removes and provider terms await
founder confirmation. It stays a measured demonstration of the open-weights path.
