- **4 Nov 2026.** The workspace can require sign-in with Firebase Authentication (Google, or email and password). It is on only when `FIREBASE_PROJECT_ID` is set, so local runs and tests stay open. The browser signs in with Firebase and trades the ID token at `POST /auth/session` for a signed, HttpOnly session cookie lasting 12 hours, because image, video and progress-stream requests cannot carry a token header. The server checks the token against Google's published keys, so no Firebase service account or extra secret leaves the project. `PREFLIGHT_ALLOWED_EMAILS` limits who comes in (emails or `@domain`) ; when signed in, an approval records the account's email instead of a typed name. Every sign-in, Google or email, then waits for a 6-digit code emailed to the account (SMTP, `PREFLIGHT_SMTP_*`): the session cookie is only set once the code is entered, a code lasts 10 minutes, allows 5 tries and can be resent once a minute, and codes are held in the server process, which suits the single worker. Because the code proves the address, the allowlist no longer needs Firebase's verified-email flag. New accounts must choose a password of at least 12 characters with upper and lower case, a number and a symbol, not containing the email name; the same rule should be set in Firebase's password policy so password resets follow it.
